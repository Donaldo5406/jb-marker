## 1. 서비스 개요 (Service)

| 항목 | 내용 |
|---|---|
| **서비스명** | JB Marker — 금융 마케팅 통합 에디터 · 준법 게이트 플랫폼 |
| **한줄 소개** | 광고를 여러 언어로 만들면서, 보내기 직전에 '이 광고가 금융법을 어기지 않았는지'를 자동으로 검사해 위반이 있으면 발송을 막아 주는 AI 마케팅 도구. 기획·디자인·준법 심의·발송 준비를 하나의 파이프라인(콕핏)으로 잇는다. |
| **개발 목표** | 생성형 AI로 광고를 '만드는' 속도는 폭증했지만(마케터 AI 사용 1년 새 33%→71%) '법에 맞는지 검수'는 여전히 사람 손이라 병목이 된다. 준법 사전심의를 파이프라인의 **하드 게이트**(통과 못 하면 발송이 잠기는 차단봉)로 내장해 'AI 대량 생성'과 '건별 사람 심의'의 구조적 충돌을 해소한다. 자율이 필요한 기획·디자인·번역은 AI가, 재현·감사가 중요한 발송·시각규제 판정은 '정해진 규칙(계산기)'이 맡아 같은 입력엔 항상 같은 결과를 보장한다. 최종 결정·법적 책임은 사람(준법감시인)에게 남기는 보조수단 설계다. |
| **타겟 사용자** | 디지털 마케터 · 준법 담당자 · 외국인 고객 접점 부서. 외국인 금융이 가장 빠르게 크는 JB금융그룹(전북은행 외국인 신용대출 72% 점유, 외국인 대출 국내 최초 1조 원 돌파)의 다국어 마케팅을 1차 적용 대상으로 한다. |
| **기대 효과** | 제작·검수 시간 약 70% 단축(캠페인 1건 19→4.7 사람-일), 언어 추가 한계비용 약 80% 절감. 허위·과장·고지 누락 위반을 발송 직전 모든 언어판에서 자동 제거해 과징금 리스크(상품 수입 최대 50%)를 사전 차단하고, 모든 판정에 '어디가·왜·어느 법 위반 + 공식 출처' 근거(영수증)를 붙여 설명·감사를 쉽게 한다. |

## 2. 시스템 구성도 (Architecture)

**3계층(프런트엔드 — 게이트웨이 — 저장소).** 모든 AI 요청이 단 하나의 통로(**Marker 게이트웨이**)를 지나 권한·근거·비용·이력이 일관 기록되고, **콘텐츠 적법성은 AI가·발송 적법성은 '정해진 규칙(계산기)'** 이 판정(같은 입력=같은 결과)한다. 모든 산출물은 공용 저장소(**VFS**)에 근거와 함께 저장된다.

```
프런트엔드 (웹) · Next.js · Vercel
  └ 콕핏 · 파일트리 · 에디터(Fabric.js) · 미리보기 · AI 챗 · 4대 스튜디오 · "동작 원리" 페이지
        ▼  REST / WebSocket
Marker 게이트웨이 — 모든 AI 요청이 지나는 단 하나의 통로
  권한 확인 → 모델 선택(Claude·GPT·Gemini) → 작업 위임 → 근거·비용·이력 자동 기록
   ├ 준법 두뇌(core)   : 숫자 검증 · 법령 출처 · 규정 판정 · 논란/평판 리스크 판정(RC)
   ├ 발송 계산기(deploy): 동의·야간·목적 규칙 · 대상 선정 (결정론)
   └ 운영(observability): 사용량 · 비용 · 세션 · 이력
        ▼
VFS — 모든 작업물·근거의 단일 저장소 (Supabase: Postgres · Storage · 로그인(JWT) · 내 데이터만 보기)
```

- **기술 스택**: Next.js · React 18 · Fabric.js v7 · TypeScript · Tailwind / FastAPI · Python 3.13 · Supabase
- **기본 모델**: claude-sonnet(텍스트) · gpt / gemini(교차검증) · gemini-image(이미지)
- 본선 신설: 제품 내 **`/architecture` "동작 원리" 페이지**(8단계 자동 루프·에이전트 루프·기술 스택을 비개발자도 이해하도록 시각화).

## 3. 핵심 기능 명세 (Feature Specification)

■ **AI Agent 3요소(공통 필수요건)** — **판단**: 대화·웹 리서치로 기획, 법령·발송 적법성·논란 리스크를 규칙/모델로 판정 / **행동**: 정보 부족 시 AskUser, 품질 미달 시 재생성, 위반 시 수정 권고·발송 잠금 / **검증·개선**: 디자인 7항목 자가 채점, 숫자 사실 확인(grounding), 수정 뒤 전체 재검토.

| 기능 | 설명 | 관련 기술 | 구현 | 본선 변경 |
|---|---|---|---|---|
| **F1. 대화로 기획·작업지시서** | 타겟·상품·채널·언어를 대화로 입력 → 기획서·작업지시서 자동 생성. 빠진 정보는 AI가 되물어 채움 | 대화형 AI + 웹 검색 + 필수항목 점검 | O | — |
| **F2. 디자인(배너) 생성·직접 수정** | 배경·문구·로고·고지를 합쳐 편집기에서 수정. 상품에 없는 가짜 금리·숫자는 생성 순간 차단 | 생성형 AI + 웹 편집기 + 숫자 사실 검증 | O | **U** 교정 재베이크 img2img 전환·브랜드 톤 수렴(§4) |

| **F6. 로그인·권한·이력·사용량** | 로그인으로 내 작업만 분리, 결과물·사용량 저장해 지난 작업·비용 추적 | 사용자 인증 + 접근 제어 + 사용량 기록 | O | — |
| **F7. 스튜디오 자료 업로드 소스화** *(본선 신설)* | Brain·Design·Review 각 스튜디오의 FileTree에서 자료(spec/plan·카피·심의 소재)를 업로드해 AI 참조원으로 사용 | 업로드 게이트(캡·확장자 검증) + `{studio}/uploads/` 저장 + 프롬프트 주입 | O | **C** 신설(§4) |

> **구현·검증 현황** — 라이브 배포(웹·서버·DB 정상) · 정기예금 4개 언어 예시로 **키·과금 없이 전 구간 시연 완주(Mock 파이프라인)** · 라이브 데모 jb-marker.vercel.app.
> F5 실발송은 본선에서도 **시뮬레이션**이며(실제 문자·카카오 채널 미연동), 소비자 결제(PG) 표면은 제품 목적 불일치로 폐기했다(§4·§5).

- **데이터 연동**: 데모용 가상 데이터를 실제 CRM·동의 명단·상품 정보와 적법 범위 내 연동.
- **확장**: 언어(4→17개)·상품(적금·외환송금·대출)·채널(문자·알림톡·이메일) 확대. 사업화 시 요금제·과금 재설계(본선에서 폐기한 소비자 결제 표면과 별개).
- **규제 대응**: 2026.1 시행 AI 기본법에 맞춰 생성물 워터마크·안내 자막 자동 삽입, 외부 인증 키에 좌우되지 않도록 불확실 시 '검증 보류' 명시 등 환각 방지 강화.
