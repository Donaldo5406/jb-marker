# 풀 디렉팅 원샷 베이크 POC (2026-07-03)

벡터 크롬 경로가 품질 기준(레퍼런스: `image copy 6` 급 실무 포스터)에 못 미쳐 폐기 판정을
받은 뒤, 대안으로 검증한 방법: **브레인스토밍(레이아웃·카피 확정) + 디자인 시스템 확정
→ 전 요소를 하나의 아트디렉터 프롬프트로 조립해 `gemini-3-pro-image`에 원샷 베이크.**
생성 스크립트는 `poc_fullbake.py` (스크래치패드 실행, 실 API).

## 정직한 격차 평가 (레퍼런스 대비)

- A의 4번 아이콘(스마트폰)은 밋밋함(세트감 3/4) — D 루프(아이콘 선확정)로 해결 가능함을 입증했으나 원샷 단독으로는 재발 가능.
- 로고는 "매우 근사한 재그리기"이지 픽셀 동일이 아님 — **로고는 기존 S2c 벡터 슬롯
  오버레이를 유지해야 함**(baked 경로가 이미 하는 방식).
- 레퍼런스의 계열사 로고 행·4줄 컴플라이언스 블록 밀도는 미시도(명세에 넣으면 될 것으로
  보이나 검증 안 됨).
- 세부 배치(예: (세전) 위치)는 프롬프트 지정과 미세하게 다를 수 있음 — 픽셀 제어가 아닌
  디렉팅임.
- 산출은 래스터 1장: 요소 단위 벡터 편집 불가. 수정은 image-edit 재호출(요소단위 AI 편집)
  또는 재베이크.

## 제품 통합 스케치 (CUD — 별도 spec 필요)

1. Brainstorming: 레이아웃(아스키/존)·카피 확정 → plan.md.
2. DesignStudio: 디자인 시스템 선확정 단계 — 팔레트·타이포 무드·아이콘 시트·히어로를
   개별 파일로 산출, 파일 뷰어로 인간 확정.
3. S2a 대체/증강: 확정 요소들(factsheet·copy·디자인 시스템·시트·히어로)을 결정론
   프롬프트 조립기로 하나의 아트디렉터 프롬프트로 합성 → gemini-3-pro-image 원샷
   (+확정 이미지들을 멀티 파트 참조로 첨부).
4. 로고: 기존 S2c 벡터 슬롯 오버레이 유지. R1 vision 리뷰(오탈자·컴플라이언스) 재사용.

비용: 원샷 1장 = 이미지 호출 1회, D 플로우 = 시트+최종 2회.
