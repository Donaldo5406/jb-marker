## 1. 프롬프트 품질 — 부수 텍스트 "가짜 글씨" 제거

**문제(실측 2026-06-30).** `gemini-3-pro-image`·Veo 실생성에서 **메인 헤드라인/바디/CTA는 한글·베트남어(성조부호 포함)까지 완벽 베이크**됨을 확인. 그러나 인물이 든 폰·노트북 화면, 배경 간판·라벨에 **판독 불가한 가짜 글씨와 임의의 'LOGO' 플레이스홀더**를 모델이 스스로 그려 넣어 광고 완성도를 떨어뜨렸다(생성 모델의 공통 약점).

**최적화.**
- 이미지 베이크·편집 지시(`design/steps.py`)에 네거티브 텍스트 규칙 추가: *"명시한 문구만 텍스트로 렌더. 그 외 어떤 텍스트·앱/UI 화면·간판·워터마크·임의 로고도 만들지 말 것. 인물이 든 기기 화면·배경 소품은 글자 없이(블랭크)."*
- 영상 footage 지시(`video/prompts.py`, `providers/google_client.py`)에 화면 회피 연출 유도: *"기기 화면은 카메라에 안 보이게/꺼진·블랭크로, 화면 없는 연출(표정·라이프스타일·공간) 우선."*
- 이미지 **검증 게이트**(비전 점검)에 소품·화면의 깨진 잔글씨/임의 'LOGO'를 **critical 결함**으로 잡는 항목을 추가(이중 방어).

**효과.** 동일 파이프라인으로 부수 텍스트 노이즈 제거 → 광고 실사 품질 상승. *(가장 가성비 높은 실결함 수정)*

## 2. 영상 렌더 시네마틱화 — "슬라이드쇼 → 광고"

**문제.** 렌더러(`video/render.py`)가 이미 생성·확정된 스토리보드의 연출 메타(`camera`/`transition`/`anim`)를 **전부 무시**하고, 하드컷·무자막장식·무음·무튜닝으로 이어붙여 **정지 이미지 슬라이드쇼**처럼 보였다. 스토리보드에 담긴(그리고 비용을 들여 생성한) 연출 정보를 실제 모션으로 되살렸다.

**최적화(전부 ffmpeg 렌더 파이프라인 개선).**

| # | 항목 | 내용 |
| --- | --- | --- |
| 1 | **자막 가독성** | 역할별 처리 — 헤드라인/CTA는 드롭섀도+외곽선, **법정 고지는 반투명 박스 스크림** → 어떤 배경 위에서도 100% 판독 |
| 2 | **키네틱 타이포** | 스토리보드의 `anim`을 소비 → 텍스트가 하드 팝이 아니라 **부드럽게 페이드 인/아웃**, 'rise' 연출은 아래에서 제자리로 |
| 3 | **켄번스(Ken Burns)** | 정지/단색 장면에 **느린 줌** 부여(정지 슬라이드 느낌 제거). 실 영상 장면은 이중 무빙 방지로 제외 |
| 4 | **컬러 그레이드** | 전 장면에 대비·채도·감마 보정 + 비네팅 + 샤픈으로 **광고 룩 통일** |
| 5 | **오디오** | 라우드니스 정규화 + 인/아웃 페이드. **CC0 음악 베드 동봉**(기존 무음 → 배경 음악) |
| 6 | **인코딩** | x264 `crf 18 / preset slow / high profile / +faststart`(웹 즉시 재생) |
| 7 | **종횡비 반영** | 스토리보드 `aspect`(9:16·16:9·1:1·4:5…)를 실제 렌더 해상도로 반영(기존 세로 하드코딩 제거) |
| 8 | **하드컷 → 크로스페이드** | 샷 전환을 **디졸브 크로스페이드**로. 콘티의 샷별 `transition`을 존중(`cut`만 하드컷) |

**8번(크로스페이드)의 정밀 처리 — 컴플라이언스 무결성.**
크로스페이드는 장면이 겹쳐 **전체 길이가 짧아진다**. 그대로 두면 (a) 자막이 영상과 어긋나고 (b) **필수 고지 노출 시간(≥3초) 규정**이 조용히 깨질 수 있다. 이를 다음으로 정밀 보정했다.
- **시간 재매핑**: 샷 k의 출력 시각 = 원래 시각 − (앞선 크로스페이드 겹침의 누적). 자막은 한 장면 안에 있으므로 시작·끝을 같은 값만큼 당겨 **노출 길이(끝−시작)가 보존**된다 → 고지 노출 시간 유지.
- **컴플라이언스 게이트**는 스토리보드(원본)를 검사하고, 렌더도 길이를 보존하므로 **규정 무결성이 유지**된다.

**검증(실물).** 실제 Veo 클립 2개로 렌더 → **h264 1080×1920 / 30fps / AAC 오디오 / 5.5Mbps**, 크로스페이드 조인트에서 전체 길이 12.0초→11.4초로 정확히 압축됨을 확인. 전환 경계 프레임을 추출해 두 장면이 50%·85%로 **디졸브 블렌드**되는 것과, 자막이 전환 구간과 겹치지 않는 것을 육안 확인.

## 3. 이미지 포스터 — 광고급 아트디렉션

**전제(실측 확정, Q1).** 실 `gemini-3-pro-image` 스모크(한국어·베트남어, 4:5, ~$0.24/장)에서 **메인 카피가 장면 조명·심도와 통합돼 완벽 베이크**됨을 확인 → **텍스트를 이미지에 굽는 "풀베이크" 방식 유지**(별도 오버레이 대비 고급, 아키텍처 변경 0).

**최적화.**
- **아트디렉션 하한선**: 베이크 프롬프트(`design/steps.py`)와 레이아웃 생성 지시(`design/prompts.py`)에 *"실제 금융 브랜드 광고 수준 — 전문 광고 사진급 자연광·시네마틱 라이팅·얕은 심도, 편집 디자인다운 그리드·여백·타이포 위계, 신뢰감 있는 브랜드 색감(스톡·클립아트·평면 지양)"* 을 명시. 장면 컨셉 품질과 무관하게 **광고급 마감의 최저선**을 보장.
- **레퍼런스 레이아웃 확충**: 기존 2종 → **5종**(중앙 정렬 히어로, 이미지 주도 하단 텍스트, 9:16 세로 스토리 등)으로 확장해 레이아웃 다양성·완성도 상향.
- **검증 게이트 강화**: 소품·화면의 깨진 잔글씨/임의 'LOGO'를 critical로 판정(§1과 연동).

*(하이브리드 오버레이 방식은 실측으로 기각됨 — 풀베이크가 더 고급.)*

## 4. 프론트엔드 — 콕핏·스튜디오 품질 폴리시

**문제.** 랜딩 페이지는 프리미엄 수준이나 **콕핏(작업 화면) 이후가 평면적·미완성**이었다: 그림자 단계가 1단(전부 평면), 전역 굵기 과다로 타이포 위계 붕괴, 일부 화면의 이모지·이질적 색·저품질 모달.

**최적화(전부 순수 디자인 폴리시).**
- **디자인 시스템 토대**: 실 elevation 그림자 스케일(4단), 전역 굵기 정상화, 웹폰트를 `next/font`로(렌더블로킹 제거), 버튼 상태(호버·포커스·마이크로인터랙션) 정비.
- **컴포넌트**: ProcessBar 이질적 보라색 → 중립 토큰, 죽은(비활성) 컨트롤 제거, VideoEditor의 이모지(`▶ ❚❚ ✓ ⚠`)를 아이콘·색 토큰으로, 결제 데모 모달을 상위 모달 수준으로 재구축.
- **레이아웃**: 디자인·영상 스튜디오가 세로 높이를 채우지 않던 버그 수정.
- **토큰 정리(D7)**: Deploy 적법성 패널의 원시 크기 클래스(`text-xs`/`text-sm`) → 디자인 토큰(`text-caption`/`text-body-sm`)으로 일관화.
- **에디터 툴바(D9)**: 아이콘 버튼에 **키보드 포커스 링(focus-visible)** + **호버 툴팁(title)** 추가, 반복 마크업을 공통 컴포넌트로 정리(접근성·발견성 향상).

> **부수 시스템 결함 수정**: 커스텀 폰트크기·색상 토큰이 같은 접두사(`text-*`)라 유틸리티 병합기가 **버튼 글자색을 누락**시키던 문제("Use Marker" 글자 안 보임)를 근본 수정(`extendTailwindMerge`). 모든 버튼에 영향.

## 5. 기능명세(CUD) 판단 — 왜 "최적화"인가

- **동작·모듈·사용자 기능 불변**: 사용자가 하는 일(「준법 포스터/영상 생성 → 검토 → 발송」)과 화면 구성·조작 흐름은 그대로다. 바뀐 것은 **생성물의 품질과 렌더링 완성도**뿐.
- **영상**: 렌더러가 *이미 생성된* 스토리보드 정보를 더 충실히 시각화할 뿐, 새 입력·새 화면·새 옵션을 추가하지 않았다.
- **이미지**: 프롬프트·레퍼런스(데이터)·검증 기준의 품질 상향. 파이프라인 단계·API 계약 불변.
- **프론트**: 순수 시각 폴리시. 컴포넌트 계약(props·testid) 보존.
- **음악 베드**: 에셋 1개 동봉(기능 아님) → 변경로그만.
- ⇒ **별도 기능명세 제출 불필요**. (안전을 위해 본 보고서를 "품질 최적화 변경 기록"으로 제출 가능.)

## 6. 검증 방식 (신뢰성)

- **영상**: 실 Veo 클립으로 실제 ffmpeg 렌더 → 산출 mp4 규격(코덱·해상도·fps·오디오·길이) 계측 + 전환/자막 프레임 육안 확인.
- **이미지**: 실 `gemini-3-pro-image` 스모크로 한글·베트남어 베이크 품질 실측(풀베이크 확정).
- **자동 테스트**: 렌더 빌더(자막·전환 계획·시간 재매핑·인코딩)와 프롬프트 규칙을 결정론 단위테스트로 고정(회귀 방지). 프론트 컴포넌트·타입체크 통과.
- **환경 주의**: 로컬 검증 중 Windows 특유 이슈(영상 자막 폰트 경로) 1건은 배포 환경(Linux)과 무관함을 확인하고 우회했다.
