## 1. Summary

금융 마케팅은 "더 많이, 더 빠르게 만드는 것"이 문제가 아니라 **"규제를 통과하면서 빠르게 만드는 것"**이 문제입니다. 동일 상품 하나도 채널 × 언어 × 고객 세그먼트의 조합 수만큼 콘텐츠를 개별 제작해야 하고, 그 각각이 금융소비자보호법·정보통신망법·개인정보보호법·표시광고법과 협회 사전심의를 통과해야 합니다. 그래서 생성형 AI로 콘텐츠를 대량 생산할수록, **"건별 사람 심의"라는 규제 구조와 더 크게 충돌**합니다. 이것이 금융 마케팅 자동화가 풀지 못한 진짜 병목입니다.

**JB Marker는 이 충돌을 "준법을 파이프라인에 내장"하는 방식으로 해소합니다.** 마케터는 콕핏(Cockpit)이라는 단일 허브에서 **기획(BrainStorming) → 디자인(Design) → 준법 심의(Review) → 발송 준비(Deploy)** 4단계를 거치며, 각 단계마다 AI 에이전트가 **판단하고, 행동하고, 스스로 검증**합니다. 핵심은 디자인 산출물이 평면 이미지가 아니라 **편집 가능한 구조화 씬(Fabric.js)**이라는 점 — 덕분에 사람이 같은 화면에서 곧바로 수동 보정할 수 있고, 텍스트 레이어만 교체해 **다국어 버전을 동등하게** 만들며, **준법 검토가 "이미지 어느 부분이 어느 조문 위반인지"를 정확히 짚을 수 있습니다.**

JB Marker는 아이디어가 아니라 **동작하는 MVP**입니다. 프런트(Vercel)·백엔드(Hugging Face Space)·DB(Supabase)가 라이브로 배포되어 있고, 자동화 테스트가 통과합니다(백엔드 `pytest` 366개 수집·클린 환경 약 360개 통과 / 프런트 `vitest` 187개, CI green). 외부 검색이 노출되지 않는 환경에서 **키·과금 없이 전 구간을 끝까지 시연**할 수 있는 Mock 데모 모드까지 갖췄습니다.

## 2. 문제 정의 (Problem Definition)

### 2.1 누가, 어떤 상황에서 겪는 문제인가

| 사용자 | 상황 | 핵심 Pain |
| --- | --- | --- |
| **디지털 마케터** | 신상품 캠페인을 여러 채널·언어로 동시에 내보내야 함 | 채널×언어×세그먼트마다 콘텐츠를 따로 만드느라 리드타임·비용이 선형 증가, 차별성 저하 |
| **준법 담당자(준법감시인·준법지원)** | 쏟아지는 콘텐츠를 게재 전 건별로 심의 | 수작업 심의가 배포 일정의 직접 병목, 검토자 간 판단 편차·누락(휴먼 에러) |
| **외국인 고객 접점 부서** | 다국어 홍보물 제작·심의 | 번역물의 필수고지 누락·의미 왜곡 리스크, **다국어 광고심의 표준 자체가 미비** |

> **현행 정량 베이스라인(가정·산식 공개)**: 마케터 1인이 분기당 약 8~10개 캠페인을 집행하고, 캠페인 1건은 채널×언어 변형 6~12개로 분화하며 변형 1건의 현행 제작 리드타임은 약 5~10영업일로 가정한다. 준법팀은 주당 수십 건을 검토하며, 명백한 사유(누락 고지·금지표현·수치 오류)로 인한 반려가 반복된다. *실제 수치는 도입 기관 데이터로 검증 필요.*

### 2.2 왜 어려운가 — 금융 마케팅은 "고규제 영역"이다

일반 소비재 광고와 달리, 금융상품 콘텐츠 **1건**은 게재 전에 아래를 **모두** 충족해야 합니다.

1. **금융소비자보호법 제22조 광고규제** — 혜택과 불이익을 균형 있게 표시(글자 크기·색상·음성 속도까지), 객관적 근거 없는 "최고·1위·유일" 등 최상급 표현 금지, 수익 보장형·오인 표현 제한, 과거 운용실적 광고 시 "미래 수익률 미보장" 표시 의무.
2. **협회 광고 사전심의(건별)** — 예: 은행연합회 자율심의(영업일 3일 내 적격/조건부/부적격), 금융투자협회는 준법감시인 사전승인 + 협회 심의를 **법령상 의무화**. 내부심의(준법감시인) + 협회심의의 **2단계 직렬** 구조.
3. **정보통신망법 제50조 전송규제** — 영리목적 광고 전송 시 명시적 사전 동의, **야간(21시~익일 08시) 별도 동의**, 전송자 표시·수신거부 수단 명시, 수신거부 즉시 중단.
4. **개인정보·신용정보법 동의·목적제한** — 마케팅 활용은 별도·개별 동의가 원칙, 자동화 결정(프로파일링) 대응권·철회권을 실시간 반영해야 함.
5. **표시·광고의 공정화에 관한 법률**(공정위) 중첩 적용 — 부당 표시·광고 시 과징금. 즉 콘텐츠 1건이 **금융위·금감원·협회 + 공정위**의 다중 규제 동시 평가 대상.

여기에 **2026년 1월 22일 시행된 AI 기본법**이 더해져, 생성형 AI 결과물에 대한 **표시의무**(텍스트 머리말·이미지 워터마크·영상 안내)가 부과됩니다. 그리고 **금융분야 AI 가이드라인의 '보조수단성' 원칙**상 AI는 의사결정 보조수단일 뿐, 최종 책임·통제는 사람에게 귀속됩니다 — **즉 "사람을 뺀 완전 자율 발행(human-out-of-the-loop)"은 원칙적으로 불가**하며, AI 심의 결과는 협회·준법 심의라는 법정 절차를 대체하거나 면책시킬 수 없습니다.

### 2.3 핵심 충돌 — 자동화가 깨지는 지점

> **"AI가 빠르게 대량 생성한 개인화 콘텐츠"와 "건별 사람 심의·동의 기반 규제 체계"는 구조적으로 충돌한다.**

리서치→생성→심의→배포를 잇는 end-to-end 자동화에서 **심의 단계가 자동화의 단절점**이 됩니다. 공개 자료상 이 단절점을 메운 사례, 그리고 **다국어 번역물의 준법 동등성을 자동 검증한 사례**는 확인되지 않습니다. 게다가 AI 생성물의 **환각**으로 금리·만기·실적 같은 수치가 틀리면, 그 즉시 금소법·표시광고법 위반이자 불완전판매 리스크가 됩니다.

### 2.4 JB의 관점 — 왜 JB금융그룹에 중요한가

JB금융그룹은 은행권 최초로 외국인 전담 플랫폼 **'BRAVO KOREA'**(17개국 출신 전담직원, 외국인 특화 점포)를 운영합니다. 2024년 말 국내 체류외국인은 **약 265만 명**(역대 최고, 장기체류 200만 명 초과)으로, **다국어 금융 마케팅의 준법 동등성**은 JB의 차별 자산을 직접 키우는 과제입니다. JB Marker의 다국어·준법 내장 파이프라인은 이 강점과 정확히 맞물립니다.

**계열사 업무 매핑**: 전북은행·광주은행의 예·적금·외환 마케팅과 **JB우리캐피탈**의 자동차할부·중금리대출 광고는 모두 금소법 제22조 + 협회 심의(은행=은행연합회 자율심의 / 캐피탈=여신금융협회 기준) + 정보통신망법 §50 발송규제를 동일하게 받습니다. JB Marker는 준법 정책을 **YAML 프로파일**로 분리해, **같은 파이프라인에서 은행·캐피탈·자산운용을 각각의 규제 기준으로** 처리할 수 있습니다.

## 3. 제안 솔루션 개요 (Solution Overview)

### 3.1 한 문장

> **콕핏이라는 단일 화면에서, 기획→디자인→준법심의→발송준비를 AI 에이전트와 사람이 함께 진행하되, "준법 통과"를 파이프라인의 하드 게이트로 박아 넣은 AI 마케터.**

### 3.2 파이프라인 — 4개의 스튜디오

```
랜딩 → 콕핏(Workspace · History · Setting) → 4-Studio 파이프라인
        ┌──────────────┬──────────────┬───────────────┬───────────────┐
        │ BrainStorming │   Design     │    Review     │    Deploy     │
        │  기획·스펙    │   디자인     │   준법 심의   │   발송 준비   │
        │  spec/plan.md │ 구조화 씬+   │ 법률·다국어   │ §50 규칙엔진  │
        │ +웹리서치+AskUser│ 다국어 텍스트│ 동등성 검토   │ +발송계획     │
        └──────────────┴──────────────┴───────────────┴───────────────┘
        ▲ 콕핏 = 항상 돌아올 수 있는 허브, 상단 프로세스 바 = 클릭 가능한 네비게이터
```

- **BrainStorming** — 마케팅 기획 전문가 페르소나의 Marker가 대화하며, **필요하면 웹검색으로 시장·트렌드를 직접 조사해** 기획서(spec.md)를 만들고, 이를 **구현계획(plan.md)**으로 변환합니다. 중간 의사결정이 필요하면 **AskUser 토스트**(Claude Code 식 선택 UI)를 웹으로 띄워 사람에게 묻습니다.
- **Design** — `plan.md`를 입력 계약으로 받아 **rough → 컴포넌트 → 최종 합성**을 거칩니다. 산출물은 평면 PNG가 아니라 **편집 가능한 구조화 씬**(배경·텍스트·로고·CTA 레이어 분리)이며, **다국어는 텍스트 레이어만 언어별로 교체**해 비주얼을 공유합니다.
- **Review** — **세 명의 검토관 페르소나**가 작동합니다. ① **법률 검토**(공식 법령 출처만 신뢰하는 화이트리스트 + 비전 AI로 이미지 검수), ② **다국어 동등성 검토**(필수고지 보존·오역·과장·누락을 언어별 비교), ③ **통합 조정**. **critical 위반이 1건이라도 있으면 다음 단계(Deploy)를 잠그는 하드 게이트**입니다.
- **Deploy** — **누구에게·언제·어떻게 보내는가가 적법한지**를 **LLM 없는 결정론 규칙엔진**으로 판정합니다(정보통신망법 §50 동의·야간·옵트아웃 + 개인정보보호법 §15 목적·§16 보유기간). 발송 대상·제외 목록(사유 + 법 인용)·야간 차단 캘린더를 산출합니다.

### 3.3 다른 시도와 무엇이 다른가

| 차별점 | 내용 | 왜 중요한가 |
| --- | --- | --- |
| **준법 사전심의 내장** | Review가 파이프라인의 하드 게이트(critical→BLOCK) | 자동화의 단절점이던 "심의"를 흐름 안으로 가져옴. 단, **법정 심의를 대체하지 않고 게재 전 반려 사유를 미리 제거** |
| **수동+AI 단일 화면** | 산출물이 편집 가능한 구조화 씬 | 사람이 같은 화면에서 즉시 보정 — '보조수단성' 원칙(사람 최종책임)과 정합 |
| **다국어 동등성** | 비주얼 공유 + 텍스트 레이어 언어별 교체·검증 | 제도 공백인 "번역물 준법 동등성"을 구조로 해결 |
| **환각 차단(grounding)** | 상품 마스터에 없는 금리·만기 토큰을 디자인 단계에서 차단 | 금융 수치 오류 = 즉시 위반. 생성 단계에서 봉쇄 |
| **추적성** | 모든 AI 산출이 VFS를 경유 → 근거·메타·이력 자동 부착 | 감사·분쟁 시 "왜 이렇게 만들었나"를 추적(설명가능성) |

## 4. 주요 기능 정의 (Key Features)

### 4.1 AI Agent 3요소 — 판단 · 행동 · 검증

본 대회의 공통 필수요건(AI가 판단하고, 행동하고, 검증·개선하는 구조)을 각 스튜디오가 충족합니다.

| 요소 | 정의 | JB Marker 구현 |
| --- | --- | --- |
| **판단** | 입력·데이터를 해석해 상태·위험·우선순위 도출 | BrainStorming: 대화로 요구사항→기획 판단 / Review: 법령 대비 위반 판정 / Deploy: §50·§15·§16 규칙 판정(BLOCK/ALLOW) |
| **행동** | 판단 결과에 따라 **다음 행동을 에이전트가 선택** | 계약 누락→AskUser 질문 vs 충족→plan 변환 / 크리틱 미달→재생성 vs 통과→다음 단계 / 위반 발견→수정 권고 vs 무위반→PASS (근거 조회·발송계획 포함) |
| **검증·개선** | 결과 점검 후 재시도/종료로 품질 관리 | Design confirm 게이트 + 1회 자동 재생성 · 디자인 크리틱(7항목 루브릭) · grounding 검사 · Review 전체 재검토 루프 |

> **자율과 결정론의 분담**: 기획·디자인·검토 권고 등 **해석·창의 영역은 LLM 에이전트가 자율 판단**하고, 발송·콘텐츠 적법성 **판정은 감사 가능성을 위해 결정론 규칙엔진**이 맡습니다. 'AI Agent'의 자율 행동과 '규제 판정'의 재현성을 의도적으로 분리했습니다.

### 4.2 스튜디오별 핵심 기능

**① BrainStorming Studio**
- 2단계 프로세스: **Stage A(웹 리서치 + 탐색 대화 → 기획서 spec.md)** + **Stage B(기획서 → 구현계획 plan.md)**.
- **Stage A 자동 웹 리서치**: 모델(Claude·GPT·Gemini)이 필요시 네이티브 웹검색으로 시장·트렌드·경쟁사 근거를 직접 조사하고, 인용을 `assets/research/`에 저장해 기획의 출처 추적성을 확보합니다(Mock 데모는 결정론 더미 리서치).
- `plan.md`는 다음 단계의 **입력 계약**: 크리에이티브 디렉션, 채널×언어 소재 매트릭스, 컴포넌트 슬롯, 이미지 컨셉, 카피 테마, 다국어 플래그·언어 목록, **상품 팩트시트(금리·만기·수수료)와 필수고지** 포함. 계약 항목이 누락되면 잠금 게이트가 진행을 차단.
- **AskUser 토스트**(WebSocket): 기획 분기·단계 확정·계약 누락 보충 3종 트리거에서 사람에게 한 번에 하나씩 질문.
- 가상 폴더 트리에 사용자가 직접 참고 자료(asset)를 추가 가능.

**② Design Studio**
- **S0**(plan.md 파싱 → 디자인 토큰 lock + 소재 매트릭스) → **S1**(레이아웃 rough) → **S2**(2a 비주얼 생성 · 2b 카피+**grounding 검증** · 2c 브랜드/필수고지) → **S3**(구조화 씬 합성 + **크리틱 패스**).
- **3액터 협업**: **Marker**(Claude 기반 하네스 — 레이아웃 스펙·카피·디자인 비평) / **Nano Banana**(Gemini 2.5 Flash Image — 텍스트 없는 배경·키비주얼만) / **Fabric.js v7**(텍스트 레이어·씬 편집·다국어 교체). **텍스트는 절대 이미지로 굽지 않고 편집 가능한 레이어로만 존재.**
- **크리틱 루브릭 7항목**(시각 위계·그리드 정합·여백 균형·CTA 명료성·컴플라이언스 톤·카피-비주얼 정합·브랜드 일관성), 평균 미달 시 자동 재생성.
- 언어별 최종 씬(`final/{ko,en,vi,zh}`)과 **메타데이터(headline/sub/cta/필수고지 + 스토리보드 콘티)** 저장 → Review가 정확히 검수.

**③ Review Studio**
- **R1 법률 검토**: 공식 법령 출처 화이트리스트(`law.go.kr`·`moleg.go.kr`·`fss.or.kr`·`fsc.go.kr`·`elaw.klri.re.kr`)만 신뢰, **(프로바이더 키 보유 시)** 비전 LLM으로 이미지·합성 렌더 검수. 조문·인용의 정밀 정합성은 LLM 검토에 의존하므로 **불확실하면 사람 확인을 요구**.
- **R2 다국어 동등성**: 필수고지 누락을 **critical로 승격**, 오역·과장·누락을 언어별 비교.
- **R3 통합 조정**: 게이트 산정(critical>0 → **BLOCKED** / 위반0 → PASS / 그 외 → WARN).
- 각 판정은 **근거 봉투**(조문·공식 출처 URL·위치(슬롯/언어)·증거)로 영속 → "어디가, 왜, 어느 법 위반인지" 포인팅.
- Review는 **수정하지 않고 권고만** 합니다. 사람이 Design에서 고친 뒤 **전체 재검토**(stale 차단).

**④ Deploy Studio**
- **D1 §50 규칙엔진**(LLM 미사용·결정론): 수신자별 opt-out / 무동의(동종상품 6개월 예외) / 야간(21~08시) / 허용을 판정 → **발송 대상·제외 목록(사유+법 인용)·24시간 캘린더**. 수신동의 예외 요건(거래관계·동종 재화/서비스·기간 등)은 **정책 YAML로 파라미터화**해 현행 원문 기준으로 설정·갱신한다.
- **D2 패키징**: 채널별 리사이즈 + 카피 적응(어드바이저).
- **발송 어드바이저 챗**(유료): 채널 믹스·허용 시간대 내 타이밍·도달 전략을 **조언만** 하고, 판정·콘텐츠는 바꾸지 않음(2중 방어로 본문 변조 차단).

> **정직한 경계**: Deploy의 실제 채널 발송은 현재 **시뮬레이션(stub)** + ZIP export까지입니다. 실 SMTP·카카오 알림톡 등 dispatch와 실 결제(PG)는 본선 고도화 범위입니다. 자세한 범위는 §7.4.

## 6. 사용자 시나리오 / 유즈케이스 (User Scenario)

### 6.1 주 시나리오 — "정기예금 캠페인을 3개 언어로, 준법까지 통과시켜 내보내기"

> 주인공: JB 디지털 마케팅팀 담당자 **민지**(분기당 약 8~10개 캠페인을 한·영·베트남어로 집행, 외국인 타겟 비중 30%+ — 가정). 신규 정기예금 상품을 한국어·영어·베트남어로, 앱푸시·알림톡·이메일에 동시 집행해야 한다.

1. **기획(BrainStorming)** — 민지가 "외국인 근로자 타겟 정기예금, 금리 강조, 신뢰감 톤"이라고 입력하면, Marker가 타겟·메시지·채널 믹스를 정리하며 **기획서**를 만든다. "베트남어를 포함할까요?" 같은 분기는 **AskUser 토스트**로 물어보고, 확정되면 **구현계획(plan.md)**으로 변환한다. 금리·만기·필수고지가 계약에 빠지면 잠금 게이트가 진행을 막는다.
2. **디자인(Design)** — 계획을 받아 레이아웃 rough → 컴포넌트 → 최종 씬을 만든다. 배경 키비주얼은 Nano Banana가, 카피·레이아웃은 Marker가, 합성·편집은 Fabric 에디터가 맡는다. **금리 "연 3.5%"가 상품 마스터와 다르면 grounding이 막는다.** 한국어 씬을 기준으로 영어·베트남어는 **텍스트 레이어만 교체**해 만든다. 민지는 마음에 안 드는 자간을 **같은 화면에서 직접 수정**한다.
3. **준법 심의(Review)** — 법률 검토관이 "최고 금리"라는 최상급 표현과 누락된 필수고지를 **공식 법령 근거와 함께 정확히 짚는다.** 다국어 검토관이 "베트남어판에 예금자보호 고지가 빠졌다"를 **critical**로 올린다 → **Deploy가 잠긴다.**
4. **수정·재검토** — 민지가 Design으로 돌아가 고지문을 추가하고 표현을 바꾼 뒤 재검토를 요청한다. 전체가 다시 검토되어 **PASS** → Deploy 잠금 해제.
5. **발송 준비(Deploy)** — §50 규칙엔진이 동의대장(데모 fixture 512명)을 훑어 **수신거부 28명을 사유·법 인용과 함께 제외**하고, 남은 484명 중 **야간 동의가 없는 312명은 21~08시 슬롯만 차단**(주간 발송은 가능), **즉시 발송 가능 172명**을 산출한다(28+312+172=512). 채널별 패키지와 야간 차단 캘린더를 만든다. 발송은 현재 시뮬레이션 + export. *(구체 인원은 데모 fixture 실행값 — 촬영·제출 전 1회 실행으로 확정)*

### 6.2 보조 유즈케이스

- **준법 담당자 관점**: 게재 전 자동 1차 검토로 **반려 사유를 미리 제거** → 사람 심의는 "검토·승인" 중심으로 전환(보조수단성 원칙 충족).
- **History 활용**: 한 캠페인에서 나온 모든 산출물·근거 문서를 단계별로 모아 보고, 디자인 시스템은 iframe으로 미리보기 → 재사용·감사.
- **Mock 데모**: 키·과금 없이 4스튜디오 전 구간을 결정적으로 완주 → 영업·교육·심사 시연에 안전.

## 7. 기대 효과 및 향후 확장성 (Expected Impact)

### 7.1 정량 기대효과 (가정 기반 추정 — 산식 공개)

> 아래는 **공개된 업계 통념과 본 서비스 구조에 근거한 예시 추정치**이며, 실제 효과는 도입 기관의 데이터로 검증해야 합니다(가정을 투명하게 공개합니다). **법정 심의(협회·준법) 소요는 그대로 두고**, JB Marker가 단축하는 **기획·제작·내부 사전검토 단계의 사람 작업**만 산정합니다.

**모델 캠페인**: 정기예금 1건 = 3개 채널 × 3개 언어 = **9개 크리에이티브 변형**.

| 단계 | 전통 방식(가정) | JB Marker(가정) | 근거 |
| --- | --- | --- | --- |
| 기획 | 2.0 person-day | 0.5 person-day | 대화형 기획 + 계약화된 plan.md |
| 디자인(9변형) | 변형당 1.0일 × 9 = 9.0 | 매트릭스 일괄 + 사람 보정 = 2.5 | 비주얼 공유 + 텍스트 레이어 교체 |
| 다국어 검수 | 2.0 | 0.5 | 동등성 자동 비교 |
| 내부 사전검토 준비 | 2.0 | 0.5 | 자동 1차 준법 검토 + 근거 포인팅 |
| **합계(사람 작업)** | **15.0 person-day** | **4.0 person-day** | — |

→ **사람 작업 약 70% 절감**(15.0 → 4.0, 정확히는 73%). *가정: 변형당 신규 제작 1 person-day, 다국어는 전통 방식에서 부분 재작업. **민감도**: 변형당 0.7일로 보수 적용 시 절감률 약 60%대로 하락 → 실효 **약 60~73% 범위**.*

| 효과 축 | 추정 | 가정·산식 |
| --- | --- | --- |
| **제작 리드타임/작업시간** | **약 70%↓** | 위 표(사람 작업 15→4 person-day) |
| **다국어 한계비용** | 언어 1개 추가 비용 **약 80~90%↓** | 비주얼·레이아웃 재사용, 텍스트 생성+동등성 검수만 추가 |
| **준법 반려·재작업** | 반려 1건당 재작업+재심의 **3~5일** 지연을 사전 제거 | 게재 전 자동 검토로 명백한 반려 사유(누락 고지·금지표현·수치 환각) 제거 |

> **규모 환산(가정)**: JB 그룹이 연간 다국어·다채널 캠페인을 약 100건 집행한다고 가정하면, 캠페인당 약 11 person-day 절감 × 100건 = **연 약 1,100 person-day 절감**. 여기에 반려율 가정(예: 15%)을 적용하면, 반려 1건당 3~5일의 재작업·재심의 지연이 추가로 제거된다. *모든 수치는 가정 기반 추정이며 산식을 공개한다.*

### 7.2 정성 기대효과

- **리스크 감소**: 환각 수치 차단 + 결정론 §50 판정 + 다국어 동등성으로 **위반·불완전판매·전송규제 위반 노출** 축소.
- **설명가능성**: 모든 산출에 근거·이력이 붙어 감사·분쟁 대응이 쉬움.
- **고객경험·AX**: 마케터와 준법이 **하나의 화면**에서 협업 → 부서 간 핑퐁 제거, 생산성·일관성 향상.
- **JB 전략 부합**: 외국인 특화금융(BRAVO KOREA)·다국어 강점을 직접 증폭, 그룹 AX·디지털 전환 서사와 정합.

### 7.4 정직한 현재 범위 (과장 배제)

> 심사 신뢰를 위해, **현재 시뮬레이션·키 의존·미구현 범위**를 명시합니다.

- **실제 발송**: 발송 어댑터는 전 채널 **stub**(`[STUB] Would dispatch...` 로그·미리보기·ZIP export). 실 dispatch는 본선 범위.
- **실 결제(PG)**: 미구현(Non-goal). 유료 게이트는 데모 우회로 시연.
- **실 LLM 품질**: 프로바이더 키가 있으면 실 LLM로 동작하나, **실 LLM로 전 구간을 완주한 품질 검증은 진행 중**. 시연은 결정적 **Mock 데모**로 흐름의 완결성을 보임 + 실 LLM 산출물 1세트를 별도 캡처.
- **법률 검토 신뢰도**: 공식 출처 **도메인**은 화이트리스트로 강제하나, 조문·인용의 정밀 정합성은 LLM 검토 의존 → "100% 자동 차단"이 아니라 **"불확실하면 사람 확인을 요구"**하는 보수적 게이트.
