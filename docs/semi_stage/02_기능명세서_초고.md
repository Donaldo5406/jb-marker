## 1. 서비스 개요 (Service)

**JB Marker**는 금융 마케팅 홍보물의 **기획 → 디자인 → 준법 심의 → 발송 준비**를 하나의 파이프라인으로 잇는 멀티 기능 에디터 플랫폼이다. 핵심은 **준법 사전심의를 파이프라인의 하드 게이트로 내장**하여, 'AI 대량 생성'과 '건별 사람 심의'의 구조적 충돌을 해소하는 것이다.

| 구분 | 내용 |
| --- | --- |
| 사용자 | 디지털 마케터 · 준법 담당자 · 외국인 고객 접점 부서 |
| 단일 허브 | **콕핏(Cockpit)** — Workspace(작업) / History(이력) / Setting(설정) |
| 파이프라인 | **BrainStorming → Design → Review → Deploy** (4 스튜디오, 프로세스 바로 네비게이트) |
| 운영 원칙 | 상태의 유일 주인 = 저장소(VFS/Supabase) · LangGraph 미사용 · 로컬 우선(키 없어도 부팅) · 모든 AI 산출은 VFS 경유(근거·이력 자동 부착) |
| AI 액터 | **Marker**(Claude 기반 하네스) · **Nano Banana**(Gemini 2.5 Flash Image) · **Fabric.js v7**(에디터) |
| 구현 상태 | 라이브 배포(Vercel·HF Space·Supabase) · 테스트 백 `pytest` 366 수집/클린 약 360 통과 · 프런트 `vitest` 187(54 files), CI green |

## 3. 핵심 기능 명세 (Feature Specification)

### 3.1 AI Agent 3요소 매핑 (공통 필수요건)

| 요소 | 구현 |
| --- | --- |
| **판단** | BrainStorming 대화로 요구사항→기획 / Review 법령 대비 위반 판정 / Deploy §50·§15·§16 규칙 판정(BLOCK·ALLOW) |
| **행동** | 판단에 따라 다음 행동 선택 — 계약 누락→AskUser / 크리틱 미달→재생성 / 위반→수정 권고 / 무위반→PASS · 법령 근거 조회·발송 계획 포함 |
| **검증·개선** | Design confirm 게이트 + 1회 자동 재생성 · 크리틱(7항목) · grounding · Review 전체 재검토 루프 |

### 3.2 스튜디오별 입력 → 처리 → 출력 → 게이트

| 스튜디오 | 입력 | 처리 | 출력(VFS) | 게이트 |
| --- | --- | --- | --- | --- |
| **BrainStorming** | 사용자 대화·참고 asset | Stage A 대화형 탐색→spec.md · Stage B spec→plan.md · AskUser 훅 | `spec.md`, `plan.md`(계약) | ⓪계약 누락 검증 → 충족 시 `step_status.brainstorming=done` |
| **Design** | `plan.md` | S0 토큰 lock+소재매트릭스 → S1 rough → S2(2a 비주얼·2b 카피+grounding·2c 브랜드/고지) → S3 합성+크리틱 → 다국어 텍스트 스왑 | `final/{ko,en,vi,zh}.scene`, `metadata.md` | confirm 게이트(단계별) · 크리틱 평균 미달 시 재생성 |
| **Review** | 씬·렌더·`metadata.md` | R1 법률(화이트리스트+비전) · R2 다국어 동등성 · R3 통합 조정 | `report.md`, `verdict.json`(근거 봉투) | **critical>0 → BLOCKED(Deploy 잠금) / 0 → PASS / 그외 → WARN(ack 필요)** |
| **Deploy** | review PASS/WARN-ack · 동의대장 | D1 §50 규칙엔진 → D2 채널 리사이즈+카피 적응 → D3 stub 발송+ZIP | 발송 대상·제외목록·24h 캘린더·패키지 ZIP | review 게이트 통과해야 진입 |

### 3.3 Marker API 게이트웨이 · 하네스

- **단일 choke point**: 모든 AI 호출이 게이트웨이를 경유 → ① 엔타이틀먼트 검사 ② 프로바이더 해석 ③ `harness.handle_turn` 위임. → 근거·이력·과금이 일관 적용.
- **하네스 6요소**: `system_prompt` · `constraints`(디자인 토큰 등) · `references`(few-shot) · `structured_output` · `critic`(품질 게이트) · `askuser_hook`. **'Marker' = 이 6요소 + 공유 VFS CRUD를 씌운 Claude**.
- **무료/raw 경로**: `PassthroughHarness`(Claude/GPT/Gemini 직접) — 산출은 `_passthrough.md`로 보존.
- **엔타이틀먼트**: `{marker, deploy}` 2-플래그. Design/Review = marker 게이트, Deploy 진입·advisor = deploy 게이트.

### 3.4 준법 엔진 — 결정론(LLM 미사용)

| 레이어 | 대상 | 정책 | 판정 |
| --- | --- | --- | --- |
| **Review(콘텐츠 적법성)** | "이 콘텐츠가 합법인가" | 표시광고법·금융광고규제(`rules_marketing.yaml`) + 공식 출처 화이트리스트 | severity별 critical/warning |
| **Deploy(발송 적법성)** | "누구에게·언제·어떻게가 합법인가" | 정보통신망법 §50(`infomatics.yaml`) + 개인정보보호법 §15/§16(`pipa.yaml`) | opt_out → no_consent(동종상품 6개월 예외) → night(21~08시) 우선순위 |

- Deploy 규칙엔진은 **순수 함수**(`rules_engine.evaluate_recipient`) → 같은 입력에 같은 판정(재현·감사 가능).
- 다중 정책 충돌 시 **가장 강한 BLOCK** 채택. 불확실(도구 실패·렌더 부재 등)은 **WARN으로 강등**(거짓 BLOCK/PASS 방지).

### 3.5 데이터 모델 (VFS) ✦

- **경로 규약**: `/{runId}/{studio}/...` — 각 스튜디오가 VFS 1급 디렉터리.
- **`runs`(manifest)**: `run_id`(PK) · `user_id` · `title` · `current_step` · `step_status`(jsonb) · `languages`(text[]).
- **`vfs_nodes`**: `(run_id, path)`(PK) · `kind` · `mime` · `source` · `content_text` · `blob_path` · `meta`(jsonb, sidecar 흡수) · `grounds`(근거) · `hash`.
- **불변식(인터페이스 강제)**: 경로 규약 준수 · 미디어 write 시 `*.meta.json` 동시생성 · 스텝 전환 시 manifest 갱신.
- **내부 노드**(`_state.json` 재개 스냅샷 · `_messages.json` 턴 · `_session.json`)는 FileTree에서 숨김 → stateless 재개의 입력.
- **인증·격리**: Supabase Auth(익명 게스트 JWT → 이메일 업그레이드) · `require_run_owner`(교차 사용자 404) · `profiles.entitled` 영속.

## 4. 주요 기능 흐름도 (Flow)

### 4.1 단계 핸드오프 (문서/JSON 계약으로만 전달, 대화 스레드 비전파)

```
[BrainStorming] ──spec.md / plan.md──▶ [Design]
                                          │  plan.md 파싱(S0) → final/{lang}.scene + metadata.md
                                          ▼
                                       [Review] ──report.md + verdict.json──▶ 게이트 산정
                                          │
                  ┌───────────────────────┼────────────────────────┐
            critical>0 → BLOCKED      위반0 → PASS            그외 → WARN(ack)
                  │                        │                        │
        Design 수정 후 전체 재검토         └──────────┬─────────────┘
                  ▲                                   ▼
                  └───────────────────────────── [Deploy]
                                          D1 §50/§15/§16 판정 → D2 패키징 → D3 stub 발송 + ZIP
```

### 4.2 Review 게이트 판정 로직

```
for asset in 산출물:
    R1 법률 verdict + R2 동등성 verdict 수집
    필수고지 누락(missing_disclosure) → severity = critical 승격
R3 통합:  critical 개수 > 0  → review = BLOCKED  (bypass 불가, Design 수정+restart만)
          위반 == 0          → review = PASS
          그 외(warning만)   → review = WARN      (사용자 ack 시 Deploy 진입 허용)
→ step_status.review 에 기록 → Deploy 탭 잠금/해제 predicate 결정
```

### 4.3 Deploy 발송 적법성 (결정론)

```
for 수신자 in 동의대장(consent_ledger):
    if opt_out:                      제외(사유: 수신거부)
    elif not 동의 and not 동종상품6개월예외:  제외(사유: 무동의)
    elif 야간(21~08) and not 야간동의: 야간 슬롯 차단
    else:                            발송 대상
→ 발송 대상 · 제외 목록(사유 + 법 인용) · 24-slot 캘린더 산출
→ D3: StubAdapter 시뮬("[STUB] Would dispatch...") + 채널별 ZIP export
```

### 4.4 세션 수명주기 ✦

- 세션 키 = `(run_id × studio)`, 스튜디오당 1 live 세션.
- lazy heartbeat(백그라운드 reaper 없음): `active → stalled(15m) → suspended(60m) → archived(+7d retention)`.

`gateway`(brainstorming·design·review·advisor 하네스 + entitlement) · `vfs`(local·supabase·factory) · `deploy`(rules_engine·eligibility·ledger·packager·providers·adapters + policies) · `observability`(usage·pricing) · `providers`(anthropic·openai·google·fake·demo + registry) · `core`(grounding·legal_search·severity) · `history`(gallery·preview) · `session`(liveness·record·store)

### 6.3 디자인 크리틱 루브릭 (7항목, 각 1~5점)
시각 위계 · 그리드 정합 · 여백 균형 · CTA 명료성 · 컴플라이언스 톤 · 카피-비주얼 정합 · 브랜드 일관성. 평균 < 3.5 또는 단일 < 2 → 재생성. bypass ON 시 사람 승인 대체 품질 게이트.

### 6.4 마일스톤 (전 단계 완료·라이브)
M0 스캐폴드·디자인시스템 / M1 VfsStore·게이트웨이 / M2 랜딩·콕핏·네비 / M3 BrainStorming / M4 Design(Fabric v7) / M5 Review / M6 Deploy / M7-A Supabase·Auth / M7-B History / M7-C 실배포 / O1~O4 횡단 정책(세션·confirm 게이트·안정 이벤트·compaction).

### 6.5 검증·시연 ✦
- 테스트: 백엔드 `pytest` 366개 수집·클린 환경 약 360개 통과·5 skipped / 프런트 `vitest` 187개 통과(54 files), CI green. *(환경에 따라 ±, 제출 직전 클린 측정으로 확정)*
- **Mock 데모**: `DemoProvider` + 정기예금 4언어(ko·en·vi·zh) fixture로 4스튜디오 전 구간을 키·과금 없이 결정적으로 완주(요청 단위 플래그, 상태 비영속).

### 6.6 정직한 현재 범위(과장 배제)
- 발송 어댑터 = 전 채널 stub(실 dispatch 없음) · 실 결제 PG = Non-goal · 이미지 키 부재 시 1x1/단색 placeholder 폴백(`meta.image_fallback=true`) · 실 LLM 전 구간 완주 품질은 검증 진행 중 · 법률 검토는 출처 도메인만 결정론 강제(조문 정합성은 LLM 의존) · critic·grounding은 프로바이더 키 보유 시 완전 작동(키 부재 시 critic은 '검증 보류' 표기로 거짓 통과 방지 — 본선 강화 §5).

### 6.7 용어
- **VFS**: 가상 폴더 트리. 모든 산출물·메타·대화의 단일 저장소.
- **하네스**: 모델에 도메인 특화 6요소를 씌운 래퍼. 'Marker' = 금융 마케팅 하네스를 씌운 Claude.
- **grounding**: 산출물 토큰이 허용 근거(상품 마스터 등)에 있는지 검증 → 수치 환각 차단.
- **엔타이틀먼트**: 유료 기능 접근 권한 플래그(`marker`·`deploy`).
