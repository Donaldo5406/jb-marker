## 1. 서비스 개요 (Service)

**JB Marker**는 금융 마케팅 홍보물의 **기획 → 디자인(이미지·영상) → 준법 심의 → 발송 준비**를 하나의 파이프라인으로 잇는 멀티 기능 에디터 플랫폼이다. 핵심은 **준법 사전심의를 파이프라인의 하드 게이트로 내장**하여, 'AI 대량 생성'과 '건별 사람 심의'의 구조적 충돌을 해소하는 것이다.

| 구분 | 내용 |
| --- | --- |
| 사용자 | 디지털 마케터 · 준법 담당자 · 외국인 고객 접점 부서 |
| 단일 허브 | **콕핏(Cockpit)** — Workspace(작업) / History(이력) / Setting(설정) |
| 파이프라인 | **BrainStorming → 제작(Design \| Video) → Review → Deploy** 🔄 (가운데 "제작" 슬롯이 매체로 스왑 — 프로세스 바로 네비게이트) |
| 운영 원칙 | 상태의 유일 주인 = 저장소(VFS/Supabase) · LangGraph 미사용 · 로컬 우선(키 없어도 부팅) · 모든 AI 산출은 VFS 경유(근거·이력 자동 부착) |
| AI 액터 | **Marker**(Claude 기반 하네스) · **Nano Banana**(Gemini 이미지 — `gemini-3-pro-image` 풀베이크) 🔄 · **Veo**(Gemini 영상 footage 생성) 🆕 · **Fabric.js v7**(에디터) · **ffmpeg**(영상 서버 렌더) 🆕 |
| 구현 상태 | 라이브 배포(Vercel·HF Space·Supabase) · 영상 파이프라인 P1~P5 머지·배포(PR#74~#88) 🆕 · 테스트 백 `pytest`/프런트 `vitest` CI green |

## 3. 핵심 기능 명세 (Feature Specification)

### 3.1 AI Agent 3요소 매핑 (공통 필수요건)

| 요소 | 구현 |
| --- | --- |
| **판단** | BrainStorming 웹 리서치+대화로 요구사항→기획 / Review 법령 대비 위반 판정 / Deploy §50·§15·§16 규칙 판정(BLOCK·ALLOW) |
| **행동** | 판단에 따라 다음 행동 선택 — 계약 누락→AskUser / 크리틱 미달→재생성 / 위반→수정 권고 / 무위반→PASS · 법령 근거 조회·발송 계획 포함 |
| **검증·개선** | Design confirm 게이트 + 1회 자동 재생성 · 크리틱(7항목) · grounding · Review 전체 재검토 루프 |

### 3.2 스튜디오별 입력 → 처리 → 출력 → 게이트

| 스튜디오 | 입력 | 처리 | 출력(VFS) | 게이트 |
| --- | --- | --- | --- | --- |
| **BrainStorming** 🔄 | 사용자 대화·참고 asset · **매체 택일(이미지/영상)** | Stage A 웹 리서치(모델 자율)+대화형 탐색→spec.md · 검색 인용→assets/research · Stage B spec→plan.md(매체별 필드셋) · AskUser 훅 | `spec.md`, `plan.md`(계약, frontmatter `medium`) | ⓪계약 누락 검증 → 충족 시 `step_status.brainstorming=done` |
| **Design**(매체=이미지) 🔄 | `plan.md` | S0 토큰 lock+소재매트릭스 → S1 rough → **S2b 카피 확정+grounding → S2a 원-레이어 풀베이크(`gemini-3-pro-image`로 히어로 텍스트까지 이미지에 직접 베이크, 정확성 내부 재생성 ≤2회)** → S2c 브랜드/**필수고지·로고 결정론 오버레이** → S3 크리틱 · **다국어=언어별 베이크 재생성** | `final/{ko,en,vi,zh}`(베이크 이미지+고지 오버레이), `metadata.md` | confirm 게이트(단계별) · 크리틱 평균 미달 시 재생성 |
| **Video**(매체=영상) 🆕 | `plan.md`(`medium: video`) | V0 setup → V1 storyboard(서사 비트→샷·레이어·타이밍) → V2a footage(**Veo** 시네마틱 광고 씬, 텍스트-free·실패 시 still 폴백) → V2b 카피+grounding → V2c 브랜드/고지+**노출 타이밍** → V3 파이널 → **확정 시 ffmpeg 서버 렌더(concat·번인·음악)** | `storyboard.spec.json`, `footage/clip_s*.mp4`, `metadata.md`, **`review/_render/final.mp4`** | 크리틱 + **고지 노출 ≥3초 타이밍 게이트(프론트+서버 이중 검증)** |
| **Review** | 씬·렌더·`metadata.md` | R1 법률(화이트리스트+비전) · R2 다국어 동등성 · R3 통합 조정 | `report.md`, `verdict.json`(근거 봉투) | **critical>0 → BLOCKED(Deploy 잠금) / 0 → PASS / 그외 → WARN(ack 필요)** |
| **Deploy** | review PASS/WARN-ack · 동의대장 | D1 §50 규칙엔진 → D2 채널 리사이즈+카피 적응 → D3 stub 발송+ZIP | 발송 대상·제외목록·24h 캘린더·패키지 ZIP | review 게이트 통과해야 진입 |

> 🆕 **제작 슬롯 스왑**: 파이프라인 가운데 "제작" 슬롯은 브레인스토밍의 매체 택일에 따라 **Design(이미지) 또는 Video(영상) 하나로 스왑**된다(한 런=한 매체). ProcessBar는 슬롯에 매체 아이콘+액센트 틴트를 적용하고, 네비게이션 제안(`deriveNavSuggestion`)이 medium을 인지해 제작 슬롯을 결정한다.

### 3.3 Marker API 게이트웨이 · 하네스

- **단일 choke point**: 모든 AI 호출이 게이트웨이를 경유 → ① 엔타이틀먼트 검사 ② 프로바이더 해석 ③ `harness.handle_turn` 위임. → 근거·이력·과금이 일관 적용.
- **하네스 6요소**: `system_prompt` · `constraints`(디자인 토큰 등) · `references`(few-shot) · `structured_output` · `critic`(품질 게이트) · `askuser_hook`. **'Marker' = 이 6요소 + 공유 VFS CRUD를 씌운 Claude**.
- **무료/raw 경로**: `PassthroughHarness`(Claude/GPT/Gemini 직접) — 산출은 `_passthrough.md`로 보존.
- **엔타이틀먼트**: `{marker, deploy}` 2-플래그. Design/Review = marker 게이트, Deploy 진입·advisor = deploy 게이트.

### 3.4 준법 엔진 — 결정론(LLM 미사용)

| 레이어 | 대상 | 정책 | 판정 |
| --- | --- | --- | --- |
| **Review(콘텐츠 적법성)** | "이 콘텐츠가 합법인가" | 표시광고법·금융광고규제(`rules_marketing.yaml`) + 공식 출처 화이트리스트 | severity별 critical/warning |
| **Deploy(발송 적법성)** | "누구에게·언제·어떻게가 합법인가" | 정보통신망법 §50(`infomatics.yaml`) + 개인정보보호법 §15/§16(`pipa.yaml`) | opt_out → no_consent(동종상품 6개월 예외) → night(21~08시) 우선순위 |

- Deploy 규칙엔진은 **순수 함수**(`rules_engine.evaluate_recipient`) → 같은 입력에 같은 판정(재현·감사 가능).
- 다중 정책 충돌 시 **가장 강한 BLOCK** 채택. 불확실(도구 실패·렌더 부재 등)은 **WARN으로 강등**(거짓 BLOCK/PASS 방지).

### 3.5 데이터 모델 (VFS) ✦

- **경로 규약**: `/{runId}/{studio}/...` — 각 스튜디오가 VFS 1급 디렉터리.
- **`runs`(manifest)**: `run_id`(PK) · `user_id` · `title` · `current_step` · `step_status`(jsonb) · `languages`(text[]).
- **`vfs_nodes`**: `(run_id, path)`(PK) · `kind` · `mime` · `source` · `content_text` · `blob_path` · `meta`(jsonb, sidecar 흡수) · `grounds`(근거) · `hash`.
- **불변식(인터페이스 강제)**: 경로 규약 준수 · 미디어 write 시 `*.meta.json` 동시생성 · 스텝 전환 시 manifest 갱신.
- **내부 노드**(`_state.json` 재개 스냅샷 · `_messages.json` 턴 · `_session.json`)는 FileTree에서 숨김 → stateless 재개의 입력.
- **인증·격리**: Supabase Auth(익명 게스트 JWT → 이메일 업그레이드) · `require_run_owner`(교차 사용자 404) · `profiles.entitled` 영속.

### 3.6 영상 제작 파이프라인 (VideoStudio) 🆕

매체를 *영상*으로 택일하면 Design 대신 **Video 하네스**가 동작한다. 영상 = **샷 타임라인 + 동기화 레이어(footage·텍스트·오디오) + 전역 포맷** — 이미지의 2D 레이아웃에 **시간축**을 더한 형태. 백엔드는 **구조화 산출 + footage 생성**까지, 픽셀/프레임 최종 합성은 **확정 시 ffmpeg**가 맡는다.

**3레이어 분업**

| 레이어 | 역할 |
| --- | --- |
| **A. 생성(백엔드)** | V0~V3 하네스가 `storyboard.spec.json`(샷·레이어·in/out 타이밍)과 footage 클립 생성. V2a가 **Veo**로 시네마틱 광고 씬을 텍스트-free로 생성(키/실패 시 still 폴백). |
| **B. 검수(프론트 VideoEditor)** | 9:16 **라이브 프리뷰**(footage `<video>` + 오버레이 캔버스 합성·스크럽) · **타임라인**(샷 트랙 + 레이어 레인 in/out 드래그) · 슬림 인스펙터(언어별 문구·고지 미터). |
| **C. 렌더(백엔드 ffmpeg)** | "확정 → 렌더"가 편집 스펙을 받아 concat + 자막/CTA/로고 **번인** + 음악 베드 믹스 → `9:16·30fps` mp4를 **`review/_render/final.mp4`**로(이미지가 PNG를 올리는 패턴과 정합 → 리뷰/배포 연결). |

**V0~V3 단계**(design S0~S3 미러): V0 setup(토큰·소재매트릭스) → V1 storyboard → V2a footage(Veo) → V2b copy(grounding) → V2c brand/disclosure(**+노출 타이밍**) → V3 final(자기크리틱 7항목 + 타이밍/고지노출).

**영상의 비자명한 컴플라이언스 3가지**(이미지와 결정적 차이)
1. **고지 노출 시간** — 필수고지 레이어는 최소 노출 시간(임계 **≥3.0초**)을 만족해야 적법. 결정론 critic `R-VID-DISCLOSURE-TIME`(`disclosure` 레이어의 `out-in` 측정) — **프론트+서버 이중 검증**, 미달 시 "확정→렌더" 차단(서버는 422).
2. **footage 텍스트-free 계약** — Veo는 글자/숫자/로고를 굽지 않음. 규제 텍스트(고지·금리 수치)는 **결정론 번인**으로만(편집·번역·grounding 가능).
3. **수치 grounding** — 금리·금액은 copy 레이어에만, factsheet 대조(이미지와 동일 엔진 재사용).

**결정론 폴백(데모 안전)**: `GOOGLE_API_KEY`/ffmpeg 부재 시 still 클립 슬라이드쇼·대표 프레임으로 폴백. `demo` provider는 키 없이 medium=video plan→footage→렌더 폴백까지 **end-to-end 완주**(라이브 Mock 영상 시연 가능). **비목표**: TTS 보이스오버 · footage 샷 재생성 스왑 · Review 영상 프레임 비전 critic(Scope C 후속).

## 4. 주요 기능 흐름도 (Flow)

### 4.1 단계 핸드오프 (문서/JSON 계약으로만 전달, 대화 스레드 비전파)

```
[BrainStorming] ──spec.md / plan.md(medium)──▶ [제작 슬롯: Design(이미지) | Video(영상)] ← medium 택일 🆕
                                          │  Design: S0~S3 → final/{lang}(원-레이어 베이크) + metadata.md
                                          │  Video : V0~V3 → storyboard + footage → 확정 ffmpeg → review/_render/final.mp4 🆕
                                          ▼
                                       [Review] ──report.md + verdict.json──▶ 게이트 산정
                                          │
                  ┌───────────────────────┼────────────────────────┐
            critical>0 → BLOCKED      위반0 → PASS            그외 → WARN(ack)
                  │                        │                        │
      제작 스튜디오 수정 후 전체 재검토     └──────────┬─────────────┘
                  ▲                                   ▼
                  └───────────────────────────── [Deploy]
                                          D1 §50/§15/§16 판정 → D2 패키징 → D3 stub 발송 + ZIP
```

### 4.2 Review 게이트 판정 로직

```
for asset in 산출물:
    R1 법률 verdict + R2 동등성 verdict 수집
    필수고지 누락(missing_disclosure) → severity = critical 승격
R3 통합:  critical 개수 > 0  → review = BLOCKED  (bypass 불가, Design 수정+restart만)
          위반 == 0          → review = PASS
          그 외(warning만)   → review = WARN      (사용자 ack 시 Deploy 진입 허용)
→ step_status.review 에 기록 → Deploy 탭 잠금/해제 predicate 결정
```

### 4.3 Deploy 발송 적법성 (결정론)

```
for 수신자 in 동의대장(consent_ledger):
    if opt_out:                      제외(사유: 수신거부)
    elif not 동의 and not 동종상품6개월예외:  제외(사유: 무동의)
    elif 야간(21~08) and not 야간동의: 야간 슬롯 차단
    else:                            발송 대상
→ 발송 대상 · 제외 목록(사유 + 법 인용) · 24-slot 캘린더 산출
→ D3: StubAdapter 시뮬("[STUB] Would dispatch...") + 채널별 ZIP export
```

### 4.4 세션 수명주기 ✦

- 세션 키 = `(run_id × studio)`, 스튜디오당 1 live 세션. **`LIFECYCLE_STUDIOS` = brainstorming·design·video·review 4종** 🆕
- lazy heartbeat(백그라운드 reaper 없음): `active → stalled(15m) → suspended(60m) → archived(+7d retention)`.
- 🔄 **프론트 소비(T2 UX)**: 세션 상태를 `CockpitProvider`가 단일 소유 — 복원 토스트(WS `session/restored`)·만료 경고+카운트다운(heartbeat ~60s 폴링)·자동 resume·활성 세션 목록. 게이트 버튼은 백엔드 `gate.actions` 배열을 **동적 렌더**(하드코딩 제거), 타입 SSOT는 `lib/api.ts`.

### 6.6 정직한 현재 범위(과장 배제)
- 발송 어댑터 = 전 채널 stub(실 dispatch 없음) · 실 결제 PG = Non-goal · 이미지 키 부재 시 1x1/단색 placeholder 폴백(`meta.image_fallback=true`) · 실 LLM 전 구간 완주 품질은 검증 진행 중 · 법률 검토는 출처 도메인만 결정론 강제(조문 정합성은 LLM 의존) · critic·grounding은 프로바이더 키 보유 시 완전 작동(키 부재 시 critic은 '검증 보류' 표기로 거짓 통과 방지 — 본선 강화 §5).
- 🆕 **영상 경계**: footage 생성은 `GOOGLE_API_KEY`(Veo) 필요 — 부재 시 still 폴백(`meta.footage_fallback=true`). 최종 mp4 렌더는 배포 환경(HF Space)의 **ffmpeg·한글 폰트**에 의존 — 부재 시 still 슬라이드쇼/대표 프레임 결정론 폴백. Veo 실광고 씬 품질은 프롬프트 튜닝 진행 중. footage 샷 재생성·트랜지션 자유편집·TTS·Review 영상 비전 critic(Scope C)은 후속(§5). `demo` provider는 키·ffmpeg 없이 영상 e2e 완주(Mock 시연용).

### 6.7 용어
- **VFS**: 가상 폴더 트리. 모든 산출물·메타·대화의 단일 저장소.
- **하네스**: 모델에 도메인 특화 6요소를 씌운 래퍼. 'Marker' = 금융 마케팅 하네스를 씌운 Claude.
- **grounding**: 산출물 토큰이 허용 근거(상품 마스터 등)에 있는지 검증 → 수치 환각 차단.
- **엔타이틀먼트**: 유료 기능 접근 권한 플래그(`marker`·`deploy`).
