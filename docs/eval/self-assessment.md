## 개선 우선순위

### A. 제출 전 필수 (점수 직접 상승)

1. **제안서·기능명세서 PDF 작성** (4.1·4.5, 잠재 +4~5) — 7항목/6항목 양식 준수. 코드 실증과 1:1 정합되게(overclaim 금지).
2. **정량 고객가치 산정** (2.3, +1) — 제작시간↓·준법반려↓·다국어 비용↓ 추정치.
3. **시연영상 촬영** (가점 +5) — C1 Mock 토글로 무료·결정적 데모 → 5분 영상.
4. **overclaim 문구 정정** (5.5·정합성) — "자동 리서치"→"대화형 기획", "법령 근거 정확"→"공식 출처 화이트리스트 + LLM 검토", "발송 플랫폼"→"발송 적법성 판정·시뮬". D2 critique 항목 반영.

### B. 본선 고도화 (구현 강화)

5. **Review 법령 정합성 보강** — 출처 도메인 외 조문·인용 검증(로컬 법령 코퍼스/RAG).
6. **grounding 계층 강제** — VFS put 또는 하네스 공통에서 grounds 부착 불변식화. 비수치 과장 키워드(한국어) 안전망.
7. **검증/개선 키 비의존화** — critic 폴백을 중립값 대신 "검증 보류" 명시.
8. **실 발송 어댑터** 1종(예: email) 실구현으로 stub 탈피.
9. **다중사용자 권한 라우트 통합 테스트** + `ENTITLEMENT_OVERRIDE` 프로덕션 가드.
10. **테스트 `.env` 격리 픽스처**(conftest) — 환경 의존 취약성 제거.

### C. 시연/제출 일관성 메모

- 시연은 **Mock 모드(C1)로 통일**해 키 의존 약점(critic 중립값·이미지 1x1)을 노출하지 않고 흐름의 완결성을 보임.
- 단, 실제 산출물 품질 입증이 필요한 항목(4.2)은 **실 LLM E2E 산출물 1세트**(D4)를 캡처해 별도 첨부.
