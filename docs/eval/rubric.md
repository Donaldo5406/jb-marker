# D1 — JB Fin:AI Challenge 평가기준 정제본 (채점표)

> 출처: `docs/FinAI_checklist.md`(배점·세부기준) + `docs/FinAI_guideline.md`(공통요건·제출형식·규칙).
> 원문이 사이트 복사로 서식이 깨져 있어, **내용 변경 없이** 채점 가능한 표로 재구성한다.
> 이 표는 D3(자가 점검)의 채점 기준이 된다.

## 총괄

| 구분 | 평가항목 | 배점 |
| --- | --- | --- |
| 1 | 주제적합성 및 문제정의 | 20 |
| 2 | 금융업무·사업 연계성 및 고객가치 | 20 |
| 3 | AI Agent 설계 및 기술적 구현 가능성 | 20 |
| 4 | MVP 완성도 및 검증 가능성 | 20 |
| 5 | 혁신성·확장성 및 운영 리스크 관리 | 20 |
| + | 시연영상 제출 (가점) | 5 |
| | **합계** | **105** |

- 각 항목은 세부기준 5개로 구성. 항목 20점을 세부기준 5개에 **각 4점**으로 균등 배분해 채점한다(운영 가정).
- 가점(시연영상) 5점은 "주요 기능·동작 흐름이 확인 가능한 5분 이내 영상 제출" 시 부여.

## 부록 A — AI Agent 공통 필수요건 매핑 (3.1 채점 근거)

가이드라인은 모든 제출 서비스가 **판단 / 행동 / 검증·개선** 3요소를 포함하도록 요구한다.
jb-marker의 각 스튜디오를 이 3요소에 매핑한다(요약 — 실제 근거는 D3에서 코드 인용).

| 요소 | 정의 | jb-marker 구현 (스튜디오별) |
| --- | --- | --- |
| **판단** | 입력·상황·데이터를 해석해 상태·위험·우선순위 도출 | BrainStorming: 리서치→스펙 판단 / Review: 법령 대비 위반 판정 / Deploy: §50·§15·§16 규칙 판정(BLOCK/ALLOW) |
| **행동** | 판단에 따라 다음 행동 선택(추가질문·근거조회·수정안·알림·요약·예약) | AskUser 훅(중간 의사결정)·근거조회(legal_search)·수정안 생성(Design)·발송계획(Deploy) |
| **검증·개선** | 결과 점검 후 재시도/종료로 품질 관리 | Design confirm 게이트·1회 재생성·critic/grounding 품질게이트·Review 재검토 루프 |
